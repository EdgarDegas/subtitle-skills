# Video Subtitles

一个面向 Codex 的视频字幕 Skill：列出或提取视频内嵌字幕，并把电影、单集或整季内容翻译为简体中文字幕 sidecar。它以本地工作区保存来源、进度、术语和结果，支持中断后继续，不修改原视频。

## 安装

最简单的方式，是把下面这句话交给 Codex：

> 请从 https://github.com/EdgarDegas/subtitle-skills 安装 `video-subtitles` Skill。把仓库放到 Codex 的 skills 目录中，确认目录名为 `video-subtitles`，阅读 `SKILL.md`，并验证 Python、Codex CLI 登录状态以及工作区中的 FFmpeg/ffprobe 工具是否就绪。不要安装同名 Python 包，也不要修改原视频。

也可以手动克隆：

```bash
git clone https://github.com/EdgarDegas/subtitle-skills \
  "${CODEX_HOME:-$HOME/.codex}/skills/video-subtitles"
```

安装后重新打开 Codex 会话，然后直接提出任务，例如：

```text
列出这个 MKV 的字幕轨道
```

```text
把这一季翻译成简体中文字幕，先把字幕源复制到本地再开始翻译
```

```text
把已完成的中文字幕同步到视频旁边
```

## 运行要求

- Python 3.9 或更高版本，只使用标准库，不需要 `pip install`
- 已登录的 Codex CLI；模型调用复用现有登录状态
- 涉及视频探测或字幕提取时，需要 FFmpeg 和 ffprobe

FFmpeg/ffprobe 不包含在仓库中，也不会被 Python 代码自动安装。Codex 会根据当前操作系统和 CPU 架构选择可信的原生版本，放入字幕工作区的专用工具目录并完成版本校验。翻译已经暂存到本地的 SRT、重新渲染和同步 sidecar 不依赖这两个工具。

## 设计特点

### 本地优先，原视频只读

面对 NAS、SMB 或移动硬盘时，Skill 会先把完整字幕源复制或提取到本地，再进行清理、翻译和模型调用。网络共享随后即使离线，也能继续处理；全过程不会重封装或修改视频。

### 可验证、可恢复的逐条身份

每条源字幕都有稳定的整数 ID，整集来源由规范化内容的 SHA-256 指纹标识。翻译按 50 条目标字幕分块，并携带前后最多 10 条只读上下文。模型输出必须逐 ID 对齐，不能漏条、重复或擅自修改时间轴。通过校验的分块立即缓存，中断后从缺失位置继续。

### 翻译与术语维护分工明确

- **Iris** 使用 `gpt-5.6-luna` 进行字幕翻译
- **Atlas** 使用 `gpt-5.6-terra` 维护整部剧共享的 Markdown 术语表

Atlas 只获得对单个术语表文件的写权限且禁用网络；编辑失败时会恢复精确备份，并保留待重试任务，不会丢弃已经通过校验的翻译分块。

### 确定性校验与局部重试

结构、字幕 ID、删除规则和附加内容由程序校验，而不是再调用一个模型做重复审稿。可定位的问题只重试相关字幕，结构性问题才重试重叠分块；每个分块最多尝试三次，失败前已经完成的结果仍然保留。

### 针对简体中文字幕的完整策略

当前 `zh-hans` profile 不只是更换提示词，还统一负责文件命名、标点规范、术语字段、说话人标签和外语残留检测，以及双关注释等规则。删除笑声、不添加注释前缀由 Iris 按提示词执行，不使用词表硬校验。它特别关注字幕的信息揭示顺序：中文可以调整语序，但不能让观众比原文更早知道关键人物、关系或证据。

歌词和画面文字会被保留并翻译；无法自然保留的双关可以生成受约束的顶部短注，同时保留底部的正常台词。

### 工作区状态完整且可审计

字幕源、索引、已验证分块、术语任务、重试记录、最终译文、渲染映射、进度和日志都保存在工作区中。最终 SRT 由已验证记录重新渲染，因此可以在不调用模型的情况下调整整集时间偏移、重新生成结果或同步 sidecar。

### 为长任务设计

整季翻译可以在后台持续运行。启动阶段会检查 Python runner、当前模型子进程和持久化进度，后续通过紧凑状态文件监控；不会仅凭一个 PID 就误判任务健康，也不会因为恢复而重复启动翻译。

## 边界

- 当前只注册了简体中文 `zh-hans` profile
- 支持文本字幕轨道的提取和转换，不做 OCR，也不转录音频
- ASS/SSA 等格式转换为 SRT 时，复杂样式可能被简化
- 默认不会覆盖已有字幕或翻译结果，除非用户明确授权

更完整的命令、工作区布局和行为约束见 [`SKILL.md`](SKILL.md) 与 [`references/`](references/)。
